# Yahoo Fantasy NBA - 玩家傷兵名單查詢設計規格書 (Injury List Specification)

- **日期**: 2026-06-23
- **作者**: Antigravity AI
- **狀態**: 草案 (Draft)

---

## 1. 功能概述 (Feature Overview)
本功能為 LINE Bot 新增 `#傷兵 <玩家名稱>` 指令（例如 `#傷兵 韋哥`），讓聯賽經理能夠查詢聯盟中特定玩家目前的傷兵名單。本功能將自動與 LLM 意圖路由整合，支援自然語言查詢（例如「看看小謝家有誰受傷」），並以極簡、具備傷病顏色分級的白底 LINE Flex Message 回傳結果。

---

## 2. 指令格式與路由邏輯 (Command & Routing Logic)

### 2.1 精準指令格式
* **格式**：`#傷兵 <參數>`
* **範例**：`#傷兵 韋哥`、`#傷兵 小謝`

### 2.2 處理邏輯 (Execution Flow)
1. **輸入匹配**：由 `src/handlers/injury_handler.py` 處理，透過正則表達式匹配 `#傷兵\s*(.*)`。
2. **空值檢查**：若提取的 `<參數>` 為空（即僅輸入 `#傷兵`），**Bot 直接結束，略過不回覆**。
3. **玩家比對**：
   * 載入聯賽的 `team_mapping.json`（對照聯賽內註冊的玩家經理名稱）。
   * 檢查 `<參數>` 是否與對照表中的任何經理名稱相符。
   * 若**比對失敗**（無匹配玩家） ➔ **Bot 直接結束，略過不回覆**。
4. **資料查詢**：
   * 呼叫 Yahoo Fantasy API 取得該玩家隊伍（Team）的 `roster`。
   * 遍歷該 Roster 中的所有球員，篩選出 `getattr(player, 'status', None)` 不為空且非 `None` 的球員（即當前有受傷狀態者）。
5. **視覺回覆**：
   * 格式化篩選出的傷兵名單（球員姓名縮寫化，格式為 `F. Last`，例如 `Stephen Curry` ➔ `S. Curry`）。
   * 發送極簡 LINE Flex Message 傷兵卡片。

---

## 3. LLM 意圖路由整合 (LLM Intent Router Integration)

* **說明描述**：
  在 `InjuryHandler` 的 `instruction_desc` 中註冊此指令說明：
  ```
  - #傷兵 <玩家名稱>：查詢我們聯盟中特定玩家隊伍目前的傷兵名單（例如：#傷兵 韋哥）。
  ```
* **運作機制**：
  * 當用戶在單聊或群組提及 Bot 時輸入「小謝有誰受傷」、「幫我查查韋哥的傷兵名單」等文字。
  * `IntentRouter` 的 LLM Agent 會比對 `{commands_desc}` 與 `{players_list}`，自動將意圖識別並轉換成 `#傷兵 小謝` 或 `#傷兵 韋哥`。
  * 轉換後的指令重新分發給 `InjuryHandler` 執行，回傳 Flex Message。

## 4. LINE Flex Message 視覺設計 (Visual Design)

### 4.1 結構定義
* **卡片類型**：單一氣泡卡片 (Bubble)
* **Body（內容區）**：
  * **1. 玩家資訊標頭 (Header Box)**：
    * 採用預設白底風格（無深色背景、無醫院 🏥 圖示）。
    * 標題：`{玩家名稱}` （粗體大字，`xl`, 顏色 `#111111`）。
    * 副標題：`{遊戲中球隊名稱}` （小字灰色，`sm`, 顏色 `#555555`）。
  * **2. 傷兵列表區 (Injuries Box)**：
    * **有傷兵時**：以垂直列表展示受傷球員，每位球員一行：
      * **左側 (flex: 1)**：利用 `spans` 結構將縮寫球員姓名與受傷部位合併在同一個文字方塊中。
        * 球員姓名縮寫部分（例如 `L. James`）：粗體，字體小 (`sm`)，顏色 `#111111`。
        * 傷勢描述部分（例如 ` - Knee`）：普通，字體極小 (`xxs`)，顏色 `#777777`。
      * **右側 (flex: 0)**：彩色狀態標籤。寬 42px、高 20px，文字為白色粗體、置中。
    * **無傷兵時**（全隊健康）：
      * 顯示一個綠色勾勾 `🟢` 圖示與文字 `目前全隊球員皆健康！`。

### 4.2 傷病狀態標籤顏色對照表
* **`O` / `INJ` / `Out` (出賽成疑/確定缺陣)**：**深紅色** (`#922B21`)
* **`Doubtful` (極低機率出賽)**：**紅橘色** (`#D35400`)
* **`Questionable` / `DTD` (可能缺陣/每日觀察)**：**橘色** (`#E67E22`)
* **`Probable` / `GTD` (高機率出賽/賽前決定)**：**黃橘色/黃色** (`#F1C40F`)
* **其他狀態 (如 `SSP` 禁賽)**：**灰色** (`#7F8C8D`)

## 5. 測試計畫 (Testing Plan)
1. **單元測試 (`tests/handlers/test_injury_handler.py`)**：
   * 驗證姓名縮寫化邏輯是否正確。
   * 驗證 Flex Message 的全新 JSON 結構（Header 雙層文字、Body 無守備位置/球隊欄位、`spans` 合併姓名與傷勢）。
   * 驗證空值與無效玩家的忽略行為。
2. **意圖路由測試 (`tests/test_intent_router.py`)**：
   * 驗證自然語言能被正確轉化並分發。
