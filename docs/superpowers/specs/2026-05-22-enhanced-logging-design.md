# 設計規範：增強執行流程日誌 (Enhanced Execution Logging)

## 1. 背景與目標
目前專案的日誌訊息不夠直觀，且缺乏細節，難以讓開發者透過終端機快速判斷當前的執行進度與瓶頸。
**目標**：建立標準化的日誌格式，詳盡追蹤從指令接收、數據抓取（細分階段）到圖表產生的完整流程。

## 2. 標準化格式
日誌將使用統一的標籤前綴，以便快速閱讀：
*   `[LINE]`：與 LINE Bot 請求處理相關。
*   `[CACHE]`：與圖片或數據快取檢查相關。
*   `[LOCK]`：與併發執行鎖檢查相關。
*   `[YAHOO]`：與 Yahoo Fantasy API 抓取相關。
*   `[PROCESS]`：與數據清洗、計算相關。
*   `[VISUAL]`：與 HTML 渲染、圖片截圖相關。
*   `[TASK]`：與背景任務 (main.py) 的起始與結束相關。

## 3. 實作細節

### 3.1 bot.py 的變更
*   **指令接收**：記錄收到的原始訊息文字。
*   **快取檢查**：記錄命中 (Hit) 或未命中 (Miss) 的檔案路徑。
*   **鎖檢查**：記錄是否因正在更新中而跳過。
*   **啟動任務**：記錄 `subprocess` 啟動 `main.py` 的動作。

### 3.2 main.py 的變更
*   **任務狀態**：啟動與完成的顯著提示。
*   **抓取細分**：
    *   `[YAHOO] 抓取賽季總數據 (Season Standings)...`
    *   `[YAHOO] 抓取第 X 週週戰績 (Weekly Stats)...`
    *   `[YAHOO] 抓取 YYYY-MM-DD 當日數據 (Daily Stats)...`
*   **視覺化階段**：
    *   `[VISUAL] 正在渲染統計 HTML 模板...`
    *   `[VISUAL] 正在進行截圖並儲存至: <path>`

## 4. 驗證標準
1. 觸發一次查詢後，終端機能依序出現對應的標籤日誌。
2. 能夠明確從日誌中區分出當前正在抓取的是賽季、週還是當日數據。
